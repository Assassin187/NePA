## Why

M1-12 has completed and archived the revision-evaluation, circuit-breaker, and controlled-degradation mechanism, but NePA still lacks the real-run evidence required by M1 D1.14 to distinguish planning defects from local implementation defects and to justify production revision parameters. M1-13 is therefore the next serial work item: it must study naturally occurring F0/F1 failures while production F2/F3 limits remain `0/0`, without treating synthetic mechanism fixtures as evidence of natural incidence.

## What Changes

- Establish a preregistered M1-13 study over real complete runs whose frozen configuration keeps `budgets.revision_f2_limit=0` and `budgets.revision_f3_limit=0`, with explicit inclusion, exclusion, configuration-equivalence, and evidence-integrity rules.
- Treat third-party Claude service identity as observational metadata: returned model names may be absent, aliased, or vary between calls without invalidating the study, provided the requested provider route and experiment configuration remain frozen and the observed values are disclosed.
- Allow transient endpoint interruptions, disconnects, timeouts, rate limits, and recoverable provider failures to resume the same logical run through existing bounded retry/resume behavior. An interruption is not a failed sample or group-invalidating event unless the run actually finalizes as `internal_error`; incomplete attempts and all consumed usage remain recorded.
- Produce one traceable row for every admitted F0/F1 failure sample, classifying it as a planning defect or local implementation defect or explicitly marking the evidence indeterminate, and bind the judgment and rationale to immutable Run, Plan, State, attempt, diagnostic, build, smoke, configuration, and model-identity evidence.
- Add a narrow deterministic audit/recomputation script that consumes the admitted sample manifest and existing M1 metric projection, rejects mixed or incomplete evidence, and emits sample counts, root-cause proportions, trigger observations, and separate real-versus-synthetic tables.
- Publish a version-controlled research protocol, sample manifest, recomputable results, root-cause report, and parameter recommendation under `experiments/m1-13-natural-failure-root-cause-study/`; raw Run artifacts remain under the existing ignored `runs/` boundary.
- Make recommendations for `revision.theta2`, `revision.theta6`, the F2/F3 production limits, and the related PQ-1 production parameters only from admitted real evidence. If natural failures are absent or insufficient, record that limitation, retain production limits at `0/0`, and do not claim D1.14 or production enablement.
- Require a responsible owner's explicit review and signature over the final sample set, classifications, report, parameter rationale, and stated insufficiencies before this change can be archived.
- During long real-call windows, delegate read-only progress observation to a low-cost monitoring subagent (prefer `gpt-5.6-luna` when available). The monitor may report meaningful progress, persistent interruption, completion, or required user action, but may not edit files, analyze root causes, develop code, classify samples, select parameters, or approve evidence; those responsibilities remain with the primary `gpt-5.6-sol` agent.
- Apply the responsible owner's authorized minimal provider-adapter correction discovered at implementation entry: preserve the existing `LLMResponse.model` contract while recording the third-party returned model identity exactly, or explicit absence, in provider metadata. This correction removes the endpoint-specific identity rewrite and missing-identity rejection that otherwise make the required M1-13 evidence impossible to collect.
- Apply the responsible owner's 2026-09-11 configuration correction by setting only the production `architecture_planner` role's `max_tokens` override to `65536`; keep the shared T1 limit and every other role unchanged. The limit remains one provider completion budget because the current provider contract does not expose separate reasoning and visible-body budgets.
- Preregister and execute a fresh N=5 configuration group after the `65536` override is frozen. Preserve the completed 16K groups as historical evidence and never pool them with the new group.
- **Out of scope:** changing any other production configuration; adding a separate reasoning/body-token API; invoking or calibrating PlanReviser; implementing M1-14 or M1-15; enabling TR-5/TR-9; changing S7/S8/M2 behavior; adding a public CLI or API; changing ArchitecturePlanner/TaskPlanner prompts or calibration lineage; editing `project_docs/` or archived changes; and using synthetic, injected, calibration, `internal_error`, historical 16K, or cherry-picked samples to fill the new group's natural-failure denominator.

## Capabilities

### New Capabilities

- `revision-root-cause-study`: Preregistered admission, evidence-bound classification, deterministic aggregation, parameter rationale, insufficiency handling, and responsible-owner acceptance for the M1-13 real-run root-cause study.

### Modified Capabilities

- The existing provider adapter retains its public response contract but exposes exact returned-model observation metadata, including absence, for M1-13 evidence collection. Revision, metric, configuration, persisted artifact, and public-interface requirements remain unchanged.
- Production configuration resolves `architecture_planner.max_tokens` to `65536` through a role-level override while preserving the T1 default for all other T1 roles.
