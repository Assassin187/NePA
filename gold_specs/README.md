# Gold Spec 字段说明

`mqtt-3.1.1-min-requirements.json` 是一组从不可变 MQTT 3.1.1 规范源文档中抽取并人工确认的原子需求。文件顶层描述整组需求的来源和范围，`requirements` 保存具体需求。

## 文件级字段

| 字段 | 含义 |
| --- | --- |
| `$schema` | 声明该 JSON 应遵循的 Schema 地址，用于校验文件结构和字段类型。 |
| `gold_set_id` | 这组需求集的唯一标识，方便引用或版本化。 |
| `description` | 人类可读的范围说明，包括当前需求集覆盖和不覆盖的内容。 |
| `source_sha256` | 原始 MQTT 规范文件的 SHA-256 哈希，用于确认需求来自哪一份不可变源文档。 |
| `requirements` | 原子需求对象数组；数组中的每个对象表示一条可单独实现、测试和追踪的需求。 |

## `requirements[]` 字段

| 字段 | 含义 |
| --- | --- |
| `id` | 需求的稳定唯一 ID，用于让代码、测试、证据和依赖关系准确关联到这条需求。 |
| `source` | 原文定位信息对象，包含 `section`、`page`、`locator` 和 `excerpt` 四个字段。 |
| `modality` | 原文的约束强度。例如 `MUST` 表示强制要求，`REQUIRED` 表示不可省略的定义性约束。具体允许值由 Schema 定义。 |
| `statement` | 要求实现的核心行为，是最重要的字段，应描述可验证的实现结果。 |
| `preconditions` | 触发这条规则的前提条件；为空数组表示没有记录到特定前提，通常视为普遍适用。 |
| `constraints` | 行为必须满足的具体边界或细节，例如 Remaining Length 最多使用四字节。 |
| `exceptions` | 规则不适用或需要不同处理的例外；为空数组表示没有记录到例外。 |
| `references` | 依赖或关联的其他需求 ID，表达规则之间的先后关系或规范引用关系。 |
| `confidence` | 这条需求从原文抽取并结构化后的可信度评分，范围为 `0` 到 `1`；当前 `1.0` 表示人工确认度很高。 |

## `source` 字段

在当前 JSON 结构中，题目中所说的原文定位字段位于每条需求的 `source` 对象内：

| 字段 | 含义 |
| --- | --- |
| `section` | 规范章节。 |
| `page` | PDF 页码，从 `1` 开始。 |
| `locator` | 文本行数或其他可复现的位置描述，例如 `lines 242-246`。 |
| `excerpt` | 从指定位置抽取的相关原文段落内容，用于支持该条需求的来源和解释。 |

空数组字段（`preconditions`、`constraints`、`exceptions`）应使用 `[]` 表示没有记录的项目，不要使用 `null`。`references` 中的 ID 必须对应同一需求集中的其他需求，并且不能重复。
