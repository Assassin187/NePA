## 根因与范围

1. 上下文管理只保护字节上限，没有保护完成代码修改所需的源码工作集。删除最旧对话会静默丢弃仍有用
   的源码观察，重复读取又相互逐出。重放证明“先逐出、后重读”；它对模型犹豫的影响是强推断，不是
   受控反事实成功率。
2. 会话边界破坏逐出算法的成对假设。重试在同一转录追加另一条指令，没有以当前代码观察和实际诊断
   重建一致请求。
3. 旧测试只证明字节限额和脚本化编译修复，没有证明自主编码任务需要的信息能持续保留。60000 字节
   设置虽然通过旧测试，却恶化真实流程。

继续提示“不要重读”无法恢复已丢弃字节；单纯提高上限也只会把同一问题推迟到更大工程。现有证据不要求
改变 23 任务规划器、放宽声明、导入答案或降低独立协议检查。
