## 0. 本文回答什么

把外部经验（Codex 公开实践、Claude Code 最佳实践、Anthropic C 编译器实验）与五条核心结论，转写为 NePA 可直接使用的思路。转写遵守三条规则：

1. **不以"顶级智能体这样做"直接论证 NePA 应这样做**——每条都要过 `3.4` 的差异表；
2. **区分已核实与推断**——引用本仓库事实的条目给出文件路径或行号，可直接复算；
3. **已固化的只标注位置，不重复论证**，只展开真实差距。

## 1. 前提：这批经验落在两个层级，混用是主要误用来源

| | A 层：生成侧（NePA 作为系统） | B 层：开发侧（我们开发 NePA） |
| --- | --- | --- |
| 智能体 | S1～S9 的 Agent 角色 | Claude Code / Codex |
| 人在场 | 无（`3.4`） | 在场，随时纠偏 |
| 完成判定 | 必须机器可判（`9.1.2`） | 人可主观认可 |
| 经验可移植度 | 低，需逐条过差异表 | 高，可近乎直接采用 |

**`system_design.md` 第 3 章已经完成 A 层转写**（P1～P8、`3.3` 四点吸收、`3.4` 五项差异）。因此本文的增量集中在两处：A 层剩余的真实差距，以及**B 层从未被系统写下来过**——而 M1\-4a2 的失败是一次 B 层失败，不是 A 层失败。

## 2. 核心转写：证伪回路的位置

外部经验的内核是"先生成足够好的计划，再用高质量反馈回路逐步证伪修正"。这句话在 NePA 里必须换位置：

- **单 run 内做不到**：无人可问；M1 的 S6 只有构建真值（`5.2.3`、`6.6.1` 规定 M2\-0 前所有 `acceptance.tests` 必须为空）；且能改自己承诺书的系统，完成率不再是测量结果。
- **run 间做得到，而且比交互式更严格**：每次 run 是一次证伪，`9.2` 的 N 次独立重复 + `9.3` 消融是修正回路，回路主体是研究者与开发流程，不是流水线自身。

这一换位同时解释了两件事：

1. **不可变 Plan 不是"没学到经验"，而是把证伪回路外移后的必然结果。** 回路主体在 run 外，run 内就不需要修订能力。
2. **NePA 真正要保的是外部回路转速**：单 run 成本、失败信息量、指标可重算性。凡提高外部转速的投入，都等价于"让计划错得便宜"；凡在 run 内增加自由度的改动，必须先证明不损害完成率的不可操纵性——`_review-*.md` 的"承诺层不可变 + 分解层确定性触发下可修订"就是这个前提下能开的最小缝。

## 3. 五条核心经验的逐条转写

### 3.1 让计划"错得便宜"，而不是给计划打分

**已固化。** NePA 有三个让计划错误变便宜的机制，且都在写 workspace 之前：`PLAN_LINT_AND_SIMULATE` 的发布前 dry\-run（`6.4.2`、`6.4.5`）；S4 全程只写 `_s4`、不写 workspace（`6.4.1` 末段）；`S4-G0`～`S4-G6` 七道机器门（`6.4.5`）。

**真实差距**：交互式智能体里一个坏计划的代价是一次对话往返；NePA 里是整个 run 报废（S4 无法 seal → `failed`，退出码 20）。这不是靠文档能消除的，只能靠两件事压低：把门尽量前推到最便宜的一级（§3.3），以及缩短外部回路（§2）。

**一处必须与外部经验分道**：外部经验说"没有任何计划质量打分器"。NePA **必须**有，因为分层规划本身是研究问题（A9）。但口径必须是**间接的**——以下游 `first_pass_rate` 与 `cost` 为因变量（`9.1.4` 已把 `first_pass_rate` 定为 A5/A8/A9 主因变量），而不是直接给 Plan 打分。任何直接打分机制都不得进入 `outcome` 或成为硬门（与 `6.4.8.2.1` 对质量审计的定位一致）。

### 3.2 走骨架优先

**A 层已固化，且比外部实践更强**：S5 是纯确定性模板、无 LLM 参与（`6.5`），所以"验证回路通电"这一步不可能失败，也不消耗模型预算。`3.1` 步骤 4 已明确记录这一固化。

**B 层是真实差距。** M1 的实现顺序把端到端路径卡在隔离校准之后：`10.2` 规定 M1\-4c 必须在 M1\-4a3 签字后开工，而 M1\-4a3 需要双模型各 N=20。M1\-4a2 的经验（§6）表明校准可能耗尽整个 change 额度，而 S4→S5→S6 这条路一次都没被走通过。

**建议（需按 `11.3` 裁决）**：在 M1\-4a1 完成后插入一次**一次性薄穿刺**，只回答"S4 seal → S5 物化 → S6 单任务 commit → receipt 对账能否跑通"，允许用 stub TaskPlanner 或手写最小 Plan，不回答任何架构质量问题。依据：`10.2` 已允许 M1\-4b 与 M1\-4a2/4a3 并行，结构上有空间。**前置约束**：穿刺产物必须与 `runs/_calibration` 隔离并显式标为不可消费，否则污染 D1.0/D1.3 的资格证据。

### 3.3 真值取最快可得的那个

NePA 的真值阶梯比外部经验更长，且前四级成本极低——这是相对交互式智能体的结构优势，应主动用足：

| 级 | 真值 | 量级 | 位置 |
| --- | --- | --- | --- |
| 1 | canonical hash 恒等 | ~0 | Blueprint 重算一致（`6.4.1`）、`D1.7`、`D1.8` |
| 2 | Schema 校验 | ~0 | 统一结构化输出 + 一次修复（`8.4`） |
| 3 | 确定性 lint / 闭包检查 | 秒 | `spec_lint`、`plan_lint` basic/full、`ARCH_VALIDATE` 全子门 |
| 4 | 构建 | 十秒 | `make` 与 `make SAN=1`——**M1 的唯一执行真值** |
| 5 | 行为测试 | 分钟 | L1/L2，M2 起才有（M1 强制为空） |
| 6 | 评审 / rubric | 模型调用 | PlanCritic、S3、S7；判别力未测 |

**通则**：任何新发现的硬门，必须下推到能判定它的最便宜一级，而不是就地新增一层评审。这条已在 `6.4.8.3` 末段对 `ARCH_VALIDATE` 写过，本文只是把它提升为跨阶段通则。

第 6 级是唯一未被测量判别力、同时又是唯一可能承载架构质量信号的一级——这与 §3.4 是同一个问题。

### 3.4 最高风险的任务排最前

**已部分固化。** `10.2` 把 R\-12（S4 联合门首过率，全项目最大经验未知量）的隔离校准放在 M1\-4c / M1\-5 / M1\-6 之前并严格串行——如果 S4 根本达不到，这个事实在最贵的实现开工前就暴露。这是本原则的正确应用。

**差距在第二大未知量的位置。** 排序依据应是未知量大小，而 NePA 的第二大未知量——**评审能否区分架构质量**——排得很后，PlanCritic 甚至不在校准范围内（`6.4.8`：隔离协议不运行 PlanCritic，因此 `plan_global_replans` 只能是暂定上限）。唯一有机会承载质量信号的角色，恰好是唯一未被测量的角色。按本原则它应当前移。

**已核实的证据边界（比 `_review-*.md` §1.2 的表述更弱，见 §7.3）**：

- `results/phase1/quality-inspection.json` 的 11 个候选**全部** `validator_verdict = pass`，且全部 4 模块 / 4 工作包（V\-7）；其中出现 `maximum_primary_share = 0.81`、零职责工作包、无消费者 task contract、`decision_count = 1`。
- 因此**已确认**的结论只有一条：**全门 pass 不是充分质量条件**。"判别方向可能是反的"**未被证实**——`results/phase0/phase0-report.md:28` 的原文是"validator 与工程质量并非完全反向"。

**推断（未验证）**：现有盲评数据不足以测判别力。盲评集只有 6 个候选、其中仅 1 个 validator\-pass，且三份排序中 Codex 那份自述 `independent: false`。按 `9.2`（小 N 禁报显著性），要测判别力需要专门设计的批次，不能用现有 6 样本冒充。

### 3.5 任务粒度 = 可证伪单元

**已固化，且比"约一小时 / 几百行"更严格**：任务 ≤ 4 文件、互斥、单文件预估 ≤ 400 行（`5.2` line 683、`S4-G3`）；每任务一轮构建验收 + 一次 git 提交（`6.6.1`）。所以坏计划的代价上界确实是"一个任务的工作量"。

两点必须记住：

1. **粒度上界的真实约束不是人的注意力，而是输出 token 预算。** O\-8 已登记：4 文件 × 400 行接近 16k 输出上限，可能截断。外部经验的数字与 NePA 恰好同量级，但理由不同——不要用外部经验去论证放宽这个上界。
2. **M1 的"可证伪"退化为"可编译"。** `acceptance.tests` 强制为空，空实现只要能编译就能过。因此 `D1.2` 的 `task_completion_rate = 100%` 证明的是**结构可生成、可构建**，不是行为正确。任何引用 M1 数字的文档与论文都必须显式限定这一点，否则读者会读成功能正确率。

## 5. C 编译器实验的三条推论

约 2,000 个会话产出能编译 Linux 的编译器，但大量工程投入落在测试环境、反馈机制与 GCC 这个已知正确 oracle 上；即使功能指标很强，Rust 代码质量仍明显达不到专家水平。

1. **真值基础设施就是正事，不是"还没开始正事"。** M0、M1\-4a1、M2\-0、`nepa/evalx/` 全属此类。按投入比例这类工作占大头是**正常且预期**的，不应被当作进度滞后。
2. **oracle 决定能力上界。** GCC 使编译器实验可行；NePA 的对应物是 gold Test Bundle + 参考实现。O\-15（无 gold 测试集协议的验证闭环）缺的正是这一项——**长期目标在拿到独立 oracle 之前，不能期望达到 MQTT 上的同等水平**。这应作为边界如实声明，而非当作待解决的工程项。相应地，R\-4 / V\-3（生成测试自身缺陷）是这条链的根基风险，其优先级不低于任何生成侧能力。
3. **功能指标强 ≠ 质量达标，本仓库已复现这一现象。** 即使 M2 之后 `req_pass_rate_must` 达 100%，也不能据此主张生成代码质量可接受。若要主张质量，必须另有 rubric 证据；而按 §3.1，该证据不得进入 `outcome`。

## 6. 本仓库自己的两条经验（M1\-4a2）

这两条比外部经验更有约束力，因为它们来自本项目数据。

### 6.1 有界迭代协议有隐含前提，前提不成立时它会在错框架内耗尽额度

**已核实**：V0/V1/V2 六组基线 `p0` 全为 0/5；仅替换为精确算法提示词后，DeepSeek 首次 5/5、Qwen 由 2/5 升到 5/5，修复回归 0。

V0/V1/V2 协议隐含假设"V0 已在正确框架内，只差定点缺陷"。该假设当时不成立——真实缺陷是**范式级**的（规则式表达 vs. 可执行构造算法），两次定点修改都花在错框架内。

**可复用的诊断信号**：多个模型、跨多个版本、在同一组硬门系统性失败，且首过率全为 0——这不是"再改一次就好"，而是框架错误。此时应换范式并新建 lineage，而不是消耗最后一次定点额度。这与"先生成足够好的计划"是同一件事：`6.4.8.2` 协议自身的前提也需要被检验。

### 6.2 一次正确的便宜证伪（本仓库对 §3.1 / §3.3 的正面实例）

**已核实**：H\-COMPLEX 假设"单调用任务天然过难，应拆分调用"。用 N=3 的最小实验检验，结果（`01-root-cause-report.md` §15.4）：

| 指标 | 单调用 M | 三阶段 S |
| --- | ---: | ---: |
| Stage 1 / 首次全门通过 | 1/3 | 1/3 |
| 最终全门通过 | 3/3 | 3/3 |
| repair regression | 0 | 0 |
| Provider 调用数 | 5 | 9（+80%） |
| tokens\_in | 105,217 | 192,995（+83.4%） |
| 累计 latency | 1,090,137 ms | 1,724,858 ms（+58.2%） |

结构性改动假设以远低于实现成本的代价被推翻，同时确认首要根因是提示词精度而非调用复杂度。**规则**：在为任何结构性改动（拆调用、加阶段、加角色）写设计之前，先用最小样本给它一次被推翻的机会。

| 做法 | 不采纳的理由 |
| --- | --- |
| 计划作为可自由增删的活文档 | 无人在场 + 完成率可操纵（`3.4`、`_review-*.md` §2.1） |
